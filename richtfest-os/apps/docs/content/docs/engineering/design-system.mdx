---
title: Reusable design system
description: Shared controls and layout patterns keep the workspace consistent.
---

The single web app owns the design system. Use shared shadcn/ui primitives and Richtfest semantic components rather than copying bespoke controls into each screen.

## Approved baseline

Use the official [shadcn/ui preset `b6F9Mslb0`](https://ui.shadcn.com/create?preset=b6F9Mslb0): Nova components, neutral base, indigo theme, yellow chart palette, Inter for body and inherited headings, Lucide icons, default radius, subtle menu accents and default translucent menus.

Generate primitives from this preset and preserve their theme tokens and interaction behavior. Richtfest wrappers add product meaning and density sizing; they must not replace the preset with unrelated fonts, colors or bespoke control styling. Keep preset metadata in the web app's `components.json` so future additions use the same baseline.

## Compose existing components

Use `Page`, `PageHeader` and `Section` for screen structure. Shared buttons, inputs, dialogs and tables handle interaction; `Field`, `Callout`, `Badge` and segmented controls express recurring product meanings.

Layouts follow the task: establish context, surface missing information, accept input and then present the decision. Keep one primary action per view or panel. Use actual links for navigation so keyboard access and opening in a new tab remain available.

## Refresh and session checks

On refresh, render the non-sensitive navigation shell immediately and show a content placeholder while the session is checked. Use the same shell when an initial project route is still loading its code. Do not replace the whole workspace with a loading splash, or blank an existing screen during navigation.

The session cookie preserves sign-in, but each fresh page verifies the session before showing identity or protected content. The persisted data cache restores only after the current user and workspace are verified; it never supplies authentication. Expired sessions go directly to sign-in without an automatic retry. Temporary failures keep the shell visible with a retry action in the content area.

## Density and language

Dense and Normal modes share the same components. Use the documented density and spacing tokens instead of fixed one-off sizes. Verify both modes when adding or changing a reusable component.

Application UI strings belong in both English and German locale files. Reuse shared labels where their meaning is the same.

## Mobile viewport

The app requests a fixed 100% mobile viewport, including when focusing form fields. Its viewport metadata disables user scaling, and `touch-action: pan-x pan-y` disables page pinch/double-tap zoom while preserving horizontal and vertical scrolling. Keep desktop browser zoom shortcuts intact; do not add global gesture or keyboard event cancellation. The public landing page and documentation are separate documents and do not inherit this policy.

Viewport restrictions alone do not reliably prevent iOS form-focus zoom. At widths below 768px or with a coarse primary pointer, inputs, textareas, native selects and editable content use at least 16px text in both density modes, before and during focus. This shared CSS rule intentionally overrides smaller density and workspace form styles; desktop controls keep their normal density sizing. Do not shrink mobile fields with transforms or focus-only font changes.

This native-style interaction trades away page-zoom accessibility; browser and operating-system accessibility overrides may still allow magnification. Verify narrow layouts in both density modes rather than using zoom restrictions or hidden overflow to conceal content that does not fit.

## Agentic workspace components

The project conversation uses shadcn's `MessageScroller`, `Message`, `Bubble`, `Attachment` and `Marker`. OpenUI renders the registered Richtfest components inside conversation turns and artifacts; it cannot generate arbitrary HTML, URLs or mutations. The registry snapshot is generated from the web library and checked against the server parser.

Assistant and agent message bodies render Markdown for headings, lists, tables, links and code. User-authored messages remain literal text. Raw HTML and remote images are not rendered; preserve the conversation's streaming, selection and reading-position behavior when changing the renderer.

Reading-position, selection, history-restoration and keyboard acceptance criteria are maintained in `DESIGN-PRINCIPLES.md`. Keep route and OpenUI code lazy so the initial bundle remains within budget.

Before introducing a new component, check whether an existing primitive or semantic wrapper covers the need. Extend the shared component when the behavior is reusable. Keep workflow-specific composition inside its feature.

The detailed token and interaction rules remain in `CONVENTIONS.md` and `DESIGN-PRINCIPLES.md`; avoid maintaining a second competing specification here.
