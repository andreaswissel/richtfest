## Project workspace

Opening a project shows its active threads in a rail beside the conversation. Use New thread to start another discussion, or select a thread to switch while keeping the source panel available. When the project has no active threads, the conversation area shows a composer; sending its first message creates the thread and starts the conversation. On narrower screens, open the Threads control to see the rail. The left side retains durable messages, replies, source citations, reader position and the user's unfinished draft. The right side keeps Documents, Artifacts, Runs and Tasks available without leaving the conversation. Project details, files, shared work and knowledge remain directly linked views over the same records.

Open **Project details** and choose **Edit project details** to change the project name, project address, customer association or status inline on the page. The optional address is the site's address, not the customer's billing address. Search by street, house number and city, then select a Geoapify suggestion with the pointer or arrow keys and Enter. Suggestions favour Germany without excluding other countries. Only complete building-address results are offered; street and city centres are not site addresses. Selecting a result fills the structured address and retains its provider reference, coordinates and attribution when you save. These coordinates are not surveyed or approved geometry.

Choose **Enter address manually** for new construction, missing addresses or unavailable search. Manual edits clear the suggestion's coordinates and provenance and are marked unverified. Unselected search text cannot be saved accidentally. **Clear address** removes the address and its search metadata; **Cancel** discards all edits. Search requires server-side Geoapify configuration; without it, the form says so and manual entry remains available. The selector does not expand the 3D editor's Berlin coverage or move an existing scene.

Status is selected from Planning, Active or Completed; the labels follow the user's selected language. Choose **Save** to apply the changes. Editing requires project write access and records an audit event.

New threads start with a temporary numbered title. After the first message, the active AI provider generates a concise title when its connection is available. If generation fails or no connection is configured, the thread uses a shortened excerpt of its first message instead. Opening an older numbered thread with saved messages also attempts naming, without needing to load its oldest messages. Naming requires knowledge write access and runs in the background without blocking the conversation. Use the rename control beside any thread to set or change its title manually; the manual title is saved for everyone in the workspace and is not replaced by automatic naming.

1. Create the customer and relevant contacts, then associate a project with that customer.
2. Attach the original source files to the project. Uploading a revision creates another immutable version instead of replacing the evidence behind earlier decisions. Upload processing extracts supported text once in the background and saves it for reuse. The source reader refreshes when processing finishes; agents wait for the saved evidence rather than extracting it themselves.
3. Start a project conversation. The agent receives a bounded inventory of the project's latest ready file versions and can resolve relevant exact versions during its work. Attach an exact source version when you want to scope the request yourself or disambiguate a document. Inventory entries identify files but are not evidence until the agent reads the selected version.
4. The workspace's active provider uses the user's personal connection first, then the workspace connection for that same provider. When no credential or effort preset is configured, an error callout below the composer explains that agent replies are unavailable and links to AI connections in Settings. Messages can still be saved; after sending, the callout confirms that the message was saved but the agent could not reply.
5. Agent output streams into a stable conversation turn. Runs, source-review delegation, tool summaries, interruptions and retries remain durable and auditable.
   While a run is active, the empty composer send control becomes **Stop**; typing a message restores **Send** and lets you steer the run.
6. Review proposed artifacts and annotations against the exact source version and page. A permitted reviewer can publish the current, exact artifact revision as a reviewed source finding. The reviewed-knowledge record retains links to the artifact revision and immutable source versions; a stale or repeated review is rejected. Generated status labels cannot grant approval.

When an agent completes a supervisor review, chat gives a short handoff and an attachment to the full proposed document, rather than putting the entire concept in a summary. Select the attachment title to open its exact saved revision, or download its PDF. The document and PDF render headings, lists and tables; sources show the actual document name and cited version, with unavailable sources labeled honestly. Earlier saved artifact previews also provide the download action. To export a different revision from the artifact panel, select it and choose **Save as PDF**. PDF export does not approve a draft or certify an engineering calculation.

If a run fails, read the specific reason in chat or run details. A summary exceeding its character limit needs a shorter summary, not more tokens. Confirmed token truncation can offer a higher limit with **Yes / No / Describe what Richtfest should do differently**. Yes lets a workspace administrator double the affected role's limit (up to 128,000), with a warning about cost and model limits. It saves the workspace setting for new runs without starting one. **Retry run** still uses the failed run's original settings; send a new request to use the higher limit. No leaves settings unchanged; Describe opens the composer so you can give a different direction before sending.

Search and message links return to a stable turn. Scrolling, selecting text, opening a source, loading older history or following another run does not take the reader's place. Reopening a conversation returns to the last meaningful turn and preserves the composer draft.

## 3D location editor

Project **3D location** opens a full-width work surface: scene layers on the left, a 3D viewport in the centre and properties or planning context on the right. The editor uses the address saved in **Project details**. Missing addresses link back there; project names and customer addresses are never guessed as site addresses. Importing is an explicit project action, not an automatic change to existing projects.

Choose **Load site context** to resolve an exact house-number match in the official Berlin address register and load public buildings and tree inventory within 100 m. Coverage is currently **Berlin, Germany**; country may be blank, DE, Deutschland or Germany. Use a full street name and house number (including a letter suffix where needed), with a postal code to disambiguate. Unknown, ambiguous or unsupported addresses fail visibly rather than falling back to Giersstraße or a city centre. The job snapshots the saved address when requested, so later detail edits cannot silently retarget a running import. The resolved address and source links appear in the editor. These are unreviewed reference layers, not surveyed project geometry. Buildings are height extrusions rather than detailed roof models. Schematic trees show recorded height and crown diameter without inventing a canopy underside; missing dimensions remain unknown.

Changing project details never moves an existing scene. A mismatch notice keeps the imported address visible. To load a different address, remove planning objects and IFC overlays, save, then choose **Load project address**. This clears old reference layers and LiDAR, retains planning notes and original source files, and fences stale scene saves. Wait for any active import to finish. Existing Giersstraße scenes retain their original coordinate origin and IFC alignment; adding a matching project address does not re-geocode them. No existing project address is automatically backfilled.

The viewport uses architectural display materials, sky reflections and soft shadows to make depth easier to read in light and dark mode. Colours do not identify real façade finishes. Lighting is fixed and illustrative, not a geolocated sun or shading study. LiDAR remains an unlit measurement overlay. Framing a selected object accounts for viewport proportions without changing its geometry or coordinates.

Under **Tree inventory**, switch **Tree display** between **Schematic** (the default discs and height poles) and **Illustrative** (foliage and trunks). Illustrative trees use recorded total height and crown diameter, but canopy underside, trunk shape, species appearance and shadows are invented visual aids, never clearance evidence. Trees missing height or crown diameter remain schematic. **Measure** automatically returns trees to schematic mode; selecting another tree style exits measurement mode. This is a temporary view choice, not an edit to source records or the saved scene.

Add dimensioned vehicle envelopes, massing boxes and spatial note pins. Select an object in the viewport or layer list, edit its position, dimensions and rotation, or use **Place on ground** to move it horizontally. Coordinates are metres: X east, Y up and Z south. Y is a local reference height, not terrain-following placement. Vehicle defaults are assumptions to replace with the actual vehicle and operating envelope, including outriggers where relevant. Top, street and perspective views, framing and point-to-point measurements help inspect the scene. Measurements are visual aids, not certified survey results. **Planning context** retains meeting notes and unresolved decisions without deriving geometry or approvals from prose.

**Import IFC** parses the original file in a browser worker and adds its actual triangle geometry. The original becomes a versioned project source. Units and embedded placements are applied, then the model is centred horizontally and grounded locally. Adjust its position and rotation against the location reference; geographic alignment remains explicitly unverified. Dimensions are read-only. This is an IFC overlay, not a BIM authoring tool, automatic georeferencing or IFC export. Invalid or geometry-free files fail visibly. Large models still depend on available browser memory.

Enable **LiDAR · 2021** to request the real Berlin airborne laser scan. The current bounded loader only supports crops contained in one available LAS tile from the **Mitte archive**; missing tiles and crops spanning multiple tiles fail explicitly. A resolved Berlin address does not guarantee LiDAR coverage. Initial preparation can take several minutes: the server streams the relevant LAS tile, validates it, crops a 100 m radius and retains up to 200,000 displayed samples. Preparation is a durable background job; failed imports expose a retry action. Subsequent toggles reuse the stored cloud for that imported site. The upper-cut control hides points above the chosen local height. Ground elevation uses the median of sampled ground-class returns; it does not flatten or survey the site's terrain. The displayed point count inside a vehicle envelope is an observation of the sampled cloud, not a collision verdict. Source classification labels are not a reliable tree/building classifier.

**Do not use the editor to approve fire-service access or branch clearance.** The scan dates to February–March 2021; airborne coverage can miss canopy undersides, and trees, vehicles and the site may have changed. No returns inside an envelope does not prove that it is clear. Confirm current branch geometry, ground levels, vehicle dimensions and operational requirements through an appropriate survey and responsible specialist review.

Choose **Save scene** to persist objects, IFC source-version references and notes in the project's workspace. Undo/redo is available within the editing session, and leaving with unsaved edits requires a decision. Concurrent saves are revision-checked: if another person saved first, reload the current scene rather than overwriting their work. Reading uses project read access; imports and saves require project write access and create audit events. The scene is accessible through the tenant-scoped `/api/projects/:id/location` API, but conversation agents do not yet edit it through a dedicated tool.

## Customer addresses and billing details

In **Customers**, choose **Create customer** or **Edit customer** on an existing row. Only the company name is required. Record the company email and phone, street and address details, postal code, city, country and optional notes. Individual people remain separate contacts under **Add contact**.

Expand **Billing details** to store the invoice recipient or legal name, billing address, invoice email, VAT ID, tax number and payment terms. **Copy company address** copies the current company name and address into the billing fields; adjust them when the invoice recipient differs. This is a one-time copy, not a live link: later company-address changes do not overwrite the billing address. Blank billing fields remain unspecified rather than silently inheriting company details.

Save the form to persist the details. Existing customers can keep optional fields empty, and clearing an optional field removes its saved value. Creating and editing customers require CRM write access; records stay within their workspace and changes appear in customer activity. These fields store billing information only: they do not issue invoices, validate tax registrations, send email or process payments.

## Incoming material

Stakeholders determine the incoming formats. PDF and IFC are the initial priorities; JPEG images, native planning formats and training videos may also arrive. Storing a format and interpreting it are distinct capabilities.

Keep original files, stable IDs, revision metadata and source references. The reader labels a selected revision as an unreviewed source; “latest uploaded” does not mean authoritative. Agents may inspect ready uploads as unreviewed evidence without a prior approval step, but must not present the content as reviewed or authoritative. PDF text is read in bounded page ranges with page coverage, checksum and truncation state. Images can be previewed. Affinity Publisher (`.afpub`) files may show an embedded flattened image preview; the original remains available to download, while document text and editable layout are not extracted. Unsupported or scanned content remains explicit. Treat extracted values as proposed facts until checked. Publishing one as a reviewed source finding records human provenance; it does not approve an engineering calculation or certify compliance. Surface missing or contradictory information rather than silently filling it in.

Training videos can inform draft procedures with timestamps. A specialist confirms those procedures and exceptions before agents reuse them as approved company knowledge.

Uploads also populate a dedicated, revision-linked source model. IFC2X3/IFC4 objects, properties, declared quantities, units and selected relationships are parsed deterministically, without an LLM or geometry calculation. For documents, a single bounded AI pass proposes structured facts from saved text when the uploader still has agent-run access and the active provider is configured. It uses that person's connection first, then the workspace connection. This pass covers a bounded excerpt, not every requirement in a long document. Missing configuration, invalid evidence and interrupted attempts are recorded rather than silently retried.

Agent reads prefer those saved facts, including their units, provenance, review status and exact source evidence. If no matching document facts are available, they use relevant saved passages. Conflicting claims stay separate, and new revisions never inherit previous approvals. Human fact review is currently available through the [source-model API](/docs/architecture/agent-runtime#structured-source-model), not a separate model editor. It is distinct from artifact approval and engineering validation.

Limited excerpts are not a complete document review. Open the original or inspect an exact page when a value, drawing or omitted section needs checking. Failed or unsupported extraction is recorded rather than retried whenever an agent reads the source. New uploads get a new extraction; earlier revisions and human approvals stay unchanged. No provider call is needed to parse an IFC file, but reasoning about what its data means can still require an agent or a person.

## First calculation workflow

External sound-insulation assessment is the first planned calculation use case. A completed project, the reviewed calculations and final report establish a reference. The applicable standards, editions, assumptions and validation criteria must be agreed with the responsible specialist before calling an output correct.

Agents coordinate and propose changes; versioned deterministic functions perform calculations. Keep the input snapshot, tool version and review record with each result. The current workspace can review historical calculation documents, but a request to perform an engineering calculation reports that no validated deterministic calculation tool is available.

## Archive and restore threads

Archive a thread from its rail row to remove it from the active list for the project. This is a shared, reversible change: messages, sources and agent history remain available, and archiving does not stop running agents. Expand Archived to open or restore a thread. Archiving the selected thread switches to the next active thread, or the start view when none remain. Archive and restore require knowledge write access and record an audit event.

The Agents panel groups active and done runs and lists the supervisor alongside its delegated specialists. Open a run to inspect its conversation. A queued run is labeled as queued, keeps the crane visible in a waiting pose, and says it is waiting for a worker; the crane animation starts once execution begins. While it is running, the conversation appends concise activity milestones inline and shows the current task with a subtle animated highlight; specialist conversations use the same feed and link back to their source versions and related specialists. When the run stops, its saved milestones remain available in the conversation. Failed and cancelled runs show a recorded reason in run details and in each affected specialist row, including when the supervisor failed and stopped its child runs. Reasons name the phase and a safe failure category without exposing provider exception text. Older runs with only a generic error are identified as having no specific cause recorded. Run details also distinguish worker queue wait, the current supervisor phase, provider-call duration and the last recorded progress. Provider-call events store the phase and an opaque call ID, not prompts, source text, credentials or raw provider errors. Run rows show elapsed time (seconds for the first five minutes, then whole minutes), reported input and output tokens, and an approximate cost when the model's rate is known. Token totals come from provider usage reports; cost is an estimate and is left unavailable when pricing is unknown.
