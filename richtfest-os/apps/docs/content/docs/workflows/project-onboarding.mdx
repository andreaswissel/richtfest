## Project workspace

Opening a project shows its active and archived threads in the left rail beside the conversation. Use New thread to start another discussion, or select a thread to switch. A horizontal tab rail at the top of the right sidebar switches between **Artifacts**, **Shared work**, **Agents** and **Sources**. Artifacts, Shared work and Agents belong to the selected thread; Sources remain shared project inputs. The tab rail scrolls horizontally when the sidebar is narrow. Artifact preview cards show an excerpt, version, review status and a link to the originating run. Ownership comes from that saved run even when it is older than the recent-run list. Switching threads clears the open document and run selection. Legacy artifacts without a thread-linked run retain their direct links but are not assigned to an arbitrary thread.

When the project has no active threads, the conversation area shows a composer; sending its first message creates the thread and starts the conversation. On narrower screens, open the Threads control to see the rail. Chat retains durable messages, replies, source citations, reader position and the user's unfinished draft while resources appear alongside it. Shared work lists the selected thread's tasks and runs; newly added tasks and agent goals stay in that thread. Project details, sources and reviewed knowledge remain project-wide views.

Shared work keeps task titles on one line beside their status; narrow panels allow two title lines and place the status underneath. Click a task row, or focus it and press Enter or Space, to expand its instructions inline. When the linked agent run is available, the expanded row shows its full goal; otherwise it shows the saved task title. Collapsing a row does not change its contents or status. Completed and cancelled tasks remain accessible with muted titles. Use **Create task** in the same header to add work to the selected thread.

Open **Project details** and choose **Edit project details** to change the project name, project address, customer association or status inline on the page. The optional address is the site's address, not the customer's billing address. Search by street, house number and city, then select a Geoapify suggestion with the pointer or arrow keys and Enter. Suggestions favour Germany without excluding other countries. Only complete building-address results are offered; street and city centres are not site addresses. Selecting a result fills the structured address and retains its provider reference, coordinates and attribution when you save. These coordinates are not surveyed or approved geometry.

Choose **Enter address manually** for new construction, missing addresses or unavailable search. Manual edits clear the suggestion's coordinates and provenance and are marked unverified. Unselected search text cannot be saved accidentally. **Clear address** removes the address and its search metadata; **Cancel** discards all edits. Search requires server-side Geoapify configuration; without it, the form says so and manual entry remains available. The selector does not expand the 3D editor's Berlin and Rheinland-Pfalz coverage or move an existing scene.

Status is selected from Planning, Active or Completed; the labels follow the user's selected language. Choose **Save** to apply the changes. Editing requires project write access and records an audit event.

New threads start with a temporary numbered title. After the first message, the active AI provider generates a concise title when its connection is available. If generation fails or no connection is configured, the thread uses a shortened excerpt of its first message instead. Opening an older numbered thread with saved messages also attempts naming, without needing to load its oldest messages. Naming requires knowledge write access and runs in the background without blocking the conversation. Use the rename control beside any thread to set or change its title manually; the manual title is saved for everyone in the workspace and is not replaced by automatic naming.

1. Create the customer and relevant contacts, then associate a project with that customer.
2. Attach the original source files to the project. Uploading a revision creates another immutable version instead of replacing the evidence behind earlier decisions. Upload processing extracts supported text once in the background and saves it for reuse. The source reader refreshes when processing finishes; agents wait for the saved evidence rather than extracting it themselves.
3. Start a project conversation. The agent receives a bounded inventory of the project's latest ready file versions and can resolve relevant exact versions during its work. Attach an exact source version when you want to scope the request yourself or disambiguate a document. Inventory entries identify files but are not evidence until the agent reads the selected version.
   Choose **Chat** (default) for search, facts and explanations without specialist delegation or new artifacts. Choose **Team** for delegated investigation and findings in chat. Choose **Report**, a built-in template and exact source versions for a structured deliverable. Team and Report require supervisor execution to be enabled. Effort controls model configuration, not permission to delegate. A successful submission returns the unchanged mode selection to Chat.
   **Suggest mode** asks TypeSafe Jev for an advisory recommendation using the draft, selected-source count and bounded conversation context. It does not send source files. **Apply** only changes the selected mode; sending is a separate action. Editing the draft or sources discards the suggestion. Uncertainty, excessive context, missing credentials and errors leave the selection unchanged. This is an explicit paid request, never a background call on every keystroke.
4. The workspace's active provider uses the user's personal connection first, then the workspace connection for that same provider. When no credential or effort preset is configured, an error callout below the composer explains that agent replies are unavailable and links to AI connections in Settings. Messages can still be saved; after sending, the callout confirms that the message was saved but the agent could not reply.
5. Agent output streams into a stable conversation turn. Runs, source-review delegation, tool summaries, interruptions and retries remain durable and auditable.
   While a run is active, the empty composer send control becomes **Stop**. Typing a message restores **Send**. During an active supervisor run it steers that run, with mode changes and recommendations disabled; it never silently starts a differently configured run when steering fails.
   Recognized text-only acknowledgements such as “thanks”, “super” or “danke” are saved without starting or steering agent work. Messages that also contain a request or question, and messages with attached source versions, keep the normal execution path. This is a narrow acknowledgement check, not a general-purpose intent classifier.
6. Review proposed artifacts and annotations against the exact source version and page. A permitted reviewer can publish the current, exact artifact revision as a reviewed source finding. The reviewed-knowledge record retains links to the artifact revision and immutable source versions; a stale or repeated review is rejected. Generated status labels cannot grant approval.

When a Report completes supervisor review, chat gives a short handoff and an attachment to the full proposed document, rather than putting the entire concept in a summary. Team returns findings in chat without creating that document. Select an attachment title or an artifact card to open its exact saved revision in a large review overlay. Source attachments and source citations also open in the overlay without leaving chat; PDFs use the browser's PDF viewer, with **Open original** available in a separate tab. Escape or Close returns to the conversation. The document and PDF render headings, lists and tables; sources show the actual document name and cited version, with unavailable sources labeled honestly. To export a different revision, select it and choose **Save as PDF**. PDF export does not approve a draft or certify an engineering calculation.

In a generated document, select a passage with the pointer or keyboard, then enter a comment in the sidebar. The quoted text and its exact rendered-text offsets are saved against that immutable revision. Saved passages remain highlighted; clicking a comment's quotation scrolls to its marked passage. Highlights appear only when the saved text still matches the anchor—comments are never silently moved to another passage or newer revision. The version selector shows each revision's own comments, with reviewer and time. Native PDF previews support reading and opening; source comments use the extracted-text selection and optional page below the viewer, not freehand drawing on the PDF.

Comments also appear in the artifact's originating thread. **Continue in thread** returns to chat, where you can ask for a revision or steer an active run. Posting a comment alone does not launch paid execution. Subsequent agent execution includes up to ten recent document comments, their quotations and bounded excerpts of the exact commented revisions (12,000 characters per document, 24,000 total), with truncation marked. Planning, specialist and review phases receive this context; other threads' comments and artifact lists are excluded. Uploaded project sources remain available as shared evidence.

If a run fails, read the specific reason in chat or run details. Summary and document/section character limits are distinct from output-token limits; more tokens do not fix an overlong field. Confirmed token truncation can offer a higher limit with **Yes / No / Describe what Richtfest should do differently**. Yes lets a workspace administrator double the affected role's limit (up to 128,000), with a warning about cost and model limits. At the maximum, the explanation remains visible without an increase button. It saves the workspace setting for new runs without starting one. **Retry run** still uses the failed run's original settings; send a new request to use the higher limit. No leaves settings unchanged; Describe opens the composer so you can give a different direction before sending.

Acoustic concepts use a soft target of 12,000 characters per authored piece, not a rejection limit. Complete evidence, citations and tables are kept even when a piece or assembled section is longer. The combined report may also exceed the 60,000-character response default without shortening it. If an older acoustic run stopped at a piece, section or combined-report character cap, choose **Retry run** to resume saved work. Completed specialist work and matching sections are reused; a previously rejected, unsaved piece must be generated again. Settings stay unchanged and the finished draft still requires review. Summary, rationale and other report formats retain their hard limits; incomplete or token-truncated acoustic pieces still cannot produce a completed report.

Main conversations and specialist threads follow new output while you are at the bottom. Scroll up to read earlier messages without being pulled back down. Returning to the bottom resumes following. Selecting text inside the transcript, searching, or opening a transcript link pauses following until you choose **Latest**; selecting text elsewhere or pressing an unrelated key does not pause the chat. **Latest** returns to the newest output and keeps following subsequent updates. Sending a message also resumes following.

Search and message links return to a stable turn. Loading older history preserves the reader's position. Reopening a conversation returns to the saved visible message and preserves the composer draft; without a saved position, it opens at the latest output.

## 3D location editor

Project **3D location** opens a full-width work surface: scene layers on the left, a 3D viewport in the centre and properties or planning context on the right. The editor uses the address saved in **Project details**. Missing addresses link back there; project names and customer addresses are never guessed as site addresses. Importing is an explicit project action, not an automatic change to existing projects.

Choose **Load site context** to resolve an exact house-number match and load official building context around the saved address. Coverage is currently **Berlin and Rheinland-Pfalz, Germany**; country may be blank, DE, Deutschland or Germany. Use a full street name and house number (including a letter suffix where needed), with a postal code to disambiguate. Unknown, ambiguous or unsupported addresses fail visibly rather than falling back to Giersstraße or a city centre. The job snapshots the saved address when requested, so later detail edits cannot silently retarget a running import. The resolved address and source links appear in the editor. These are unreviewed reference layers, not surveyed project geometry. Buildings are height extrusions rather than detailed roof models.

Berlin uses its official address register, building-height layer and tree inventory in EPSG:25833. Schematic trees show recorded height and crown diameter without inventing a canopy underside; missing dimensions remain unknown. Rheinland-Pfalz uses exact house results from the state's maps.rlp.de address service and official LVermGeoRP LoD2 CityGML tiles in EPSG:25832. The import retains ground footprints, holes and recorded building heights in a 100 m bounding-box neighbourhood, fetching all intersecting 2 km tiles with bounded streaming reads. It does not import roof meshes, terrain, trees or LiDAR there; those unavailable layers are identified explicitly rather than presented as an empty survey. Missing heights remain unknown. Sources retain attribution and download links under dl-de/by-2-0. No new API key is required for these public state services. Bendenweg 6 in Alzey is within this coverage.

Changing project details never moves an existing scene. A mismatched scene is preserved but hidden by default, with both addresses shown in the notice. **View retained scene** opens it explicitly for inspection or editing; **Hide retained scene** hides it again. To load a different address, remove planning objects and IFC overlays, save, then choose **Load project address**. This clears old reference layers and LiDAR, retains planning notes and original source files, and fences stale scene saves. Wait for any active import to finish. Existing Giersstraße scenes retain their original coordinate origin and IFC alignment; adding a matching project address does not re-geocode them. No existing project address is automatically backfilled or existing scene silently migrated.

With the optional [public data catalogue](/docs/architecture/public-data) enabled, sites fully covered by its Giersstraße 20 pilot partitions pin published building/tree releases rather than fetching each source anew. Other addresses retain on-demand imports. Scheduled source updates do not change an existing project's context. Open **Public data status** in the inspector to see the pinned releases, available updates, retrieval health and source provenance. A recent check is not a recent survey or approval. **Check import status** checks the catalogue without starting a source import. With project write access and a saved address matching the imported context, choose **Refresh project context** and confirm **Adopt latest releases** to queue replacement with the latest published data at execution time. The exact coordinate frame, objects, notes, unsaved scene edits and LiDAR remain unchanged. Wait for active LiDAR imports before refreshing. The existing context remains visible while refreshing and survives failure. Legacy imports without catalogue pins keep their existing UI.

The viewport uses architectural display materials, sky reflections and soft shadows to make depth easier to read in light and dark mode. Colours do not identify real façade finishes. Lighting is fixed and illustrative, not a geolocated sun or shading study. LiDAR remains an unlit measurement overlay. Framing a selected object accounts for viewport proportions without changing its geometry or coordinates.

Under **Tree inventory**, switch **Tree display** between **Schematic** (the default discs and height poles) and **Illustrative** (foliage and trunks). Illustrative trees use recorded total height and crown diameter, but canopy underside, trunk shape, species appearance and shadows are invented visual aids, never clearance evidence. Trees missing height or crown diameter remain schematic. **Measure** automatically returns trees to schematic mode; selecting another tree style exits measurement mode. This is a temporary view choice, not an edit to source records or the saved scene.

Add dimensioned vehicle envelopes, massing boxes and spatial note pins. Select an object in the viewport or layer list, edit its position, dimensions and rotation, or use **Place on ground** to move it horizontally. Coordinates are metres: X east, Y up and Z south. Y is a local reference height, not terrain-following placement. Vehicle defaults are assumptions to replace with the actual vehicle and operating envelope, including outriggers where relevant. Top, street and perspective views, framing and point-to-point measurements help inspect the scene. Measurements are visual aids, not certified survey results. **Planning context** retains meeting notes and unresolved decisions without deriving geometry or approvals from prose.

**Import IFC** parses the original file in a browser worker and adds its actual triangle geometry. The original becomes a versioned project source. Units and embedded placements are applied, then the model is centred horizontally and grounded locally. Adjust its position and rotation against the location reference; geographic alignment remains explicitly unverified. Dimensions are read-only. This is an IFC overlay, not a BIM authoring tool, automatic georeferencing or IFC export. Invalid or geometry-free files fail visibly. Large models still depend on available browser memory.

Enable **LiDAR · 2021** to request the real Berlin airborne laser scan. The current bounded loader only supports crops contained in one available LAS tile from the **Mitte archive**; missing tiles and crops spanning multiple tiles fail explicitly. A resolved Berlin address does not guarantee LiDAR coverage. Initial preparation can take several minutes: the server streams the relevant LAS tile, validates it, crops a 100 m radius and retains up to 200,000 displayed samples. Preparation is a durable background job; failed imports expose a retry action. Subsequent toggles reuse the stored cloud for that imported site. The upper-cut control hides points above the chosen local height. Ground elevation uses the median of sampled ground-class returns; it does not flatten or survey the site's terrain. The displayed point count inside a vehicle envelope is an observation of the sampled cloud, not a collision verdict. Source classification labels are not a reliable tree/building classifier.

**Do not use the editor to approve fire-service access or branch clearance.** The scan dates to February–March 2021; airborne coverage can miss canopy undersides, and trees, vehicles and the site may have changed. No returns inside an envelope does not prove that it is clear. Confirm current branch geometry, ground levels, vehicle dimensions and operational requirements through an appropriate survey and responsible specialist review.

Choose **Save scene** to persist objects, IFC source-version references and notes in the project's workspace. Undo/redo is available within the editing session, and leaving with unsaved edits requires a decision. Concurrent saves are revision-checked: if another person saved first, reload the current scene rather than overwriting their work. Reading uses project read access; imports and saves require project write access and create audit events. The scene is accessible through the tenant-scoped `/api/projects/:id/location` API, but conversation agents do not yet edit it through a dedicated tool.

## Customer addresses and billing details

In **Customers**, choose **Create customer** or **Edit customer** on an existing row. Only the company name is required. Record the company email and phone, street and address details, postal code, city, country and optional notes. Individual people remain separate contacts under **Add contact**.

Expand **Billing details** to store the invoice recipient or legal name, billing address, invoice email, VAT ID, tax number and payment terms. **Copy company address** copies the current company name and address into the billing fields; adjust them when the invoice recipient differs. This is a one-time copy, not a live link: later company-address changes do not overwrite the billing address. Blank billing fields remain unspecified rather than silently inheriting company details.

Save the form to persist the details. Existing customers can keep optional fields empty, and clearing an optional field removes its saved value. Creating and editing customers require CRM write access; records stay within their workspace and changes appear in customer activity. These fields store billing information only: they do not issue invoices, validate tax registrations, send email or process payments.

## Incoming material

Stakeholders determine the incoming formats. PDF and IFC are the initial priorities; JPEG images, native planning formats and training videos may also arrive. Storing a format and interpreting it are distinct capabilities.

Keep original files, stable IDs, revision metadata and source references. The reader labels a selected revision as an unreviewed source; “latest uploaded” does not mean authoritative. Agents may inspect ready uploads as unreviewed evidence without a prior approval step, but must not present the content as reviewed or authoritative. PDF text is read in bounded page ranges with page coverage, checksum and truncation state. PNG, JPEG, WebP and BMP images receive German/English OCR, plus a single visual interpretation pass when a vision-capable provider is configured. This lets text-free diagrams contribute unreviewed descriptions; it does not establish exact materials, dimensions or acoustic performance from appearance. Animated images use only the first frame, with that limit recorded.

Affinity Publisher (`.afpub`) files may contain an embedded flattened image preview. OCR and visual interpretation use only that preview, which may be just the cover; they do not read the native document text, editable layout or all pages. Agent evidence retains that limitation. Export and upload a PDF for full page access. A missing preview is reported separately from an unreadable image. Existing failed or unsupported revisions can be recovered in place through the [source-model recovery API](/architecture/agent-runtime#structured-source-model), without re-uploading or changing original versions, citations or reviews. An operator explicitly queues recovery; deploying support does not start it or change completed reports.

Treat extracted values and visual inferences as proposed facts until checked. Publishing one as a reviewed source finding records human provenance; it does not approve an engineering calculation or certify compliance. Surface missing or contradictory information rather than silently filling it in.

Training videos can inform draft procedures with timestamps. A specialist confirms those procedures and exceptions before agents reuse them as approved company knowledge.

Uploads also populate a dedicated, revision-linked source model. IFC2X3/IFC4 objects, properties, declared quantities, units and selected relationships are parsed deterministically, without an LLM or geometry calculation. Documents use up to six small evidence batches to propose structured facts from saved text when the uploader still has agent-run access and the active provider is configured. Each response stays within the configured output limit; a failed batch publishes no partial model. It uses that person's connection first, then the workspace connection. These batches cover a bounded excerpt, not every requirement in a long document, and can increase total indexing cost. Missing configuration, invalid evidence and interrupted attempts are recorded rather than silently retried.

Agent reads prefer those saved facts, including their units, provenance, review status and exact source evidence. If no matching document facts are available, they use relevant saved passages. Conflicting claims stay separate, and new revisions never inherit previous approvals. Human fact review is currently available through the [source-model API](/docs/architecture/agent-runtime#structured-source-model), not a separate model editor. It is distinct from artifact approval and engineering validation.

Limited excerpts are not a complete document review. Open the original or inspect an exact page when a value, drawing or omitted section needs checking. Failed or unsupported extraction is recorded rather than retried whenever an agent reads the source. New uploads get a new extraction; earlier revisions and human approvals stay unchanged. No provider call is needed to parse an IFC file, but reasoning about what its data means can still require an agent or a person.

For legends, plan relationships and table layouts missing from OCR, supervisor-run agents with a vision-capable model and at least two model steps can inspect an exact PDF page or image crop. Up to four targeted reads per call use the original revision and record the page/crop. A successful read may support an unreviewed visual observation even when text extraction failed. It does not establish full document coverage, verified measurements or approval; unreadable or omitted content remains a gap. Recovered indexing is still important for report sections that depend on saved source evidence.

## First calculation workflow

External sound-insulation assessment is the first planned calculation use case. A completed project, the reviewed calculations and final report establish a reference. The applicable standards, editions, assumptions and validation criteria must be agreed with the responsible specialist before calling an output correct.

### Enable specialist document review

1. In **Settings → Agent model settings**, select the provider and effort preset used for the project. Keep the required Source reviewer and Requirements reviewer configurations, then enable and configure Sound insulation specialist, Construction law specialist or Cost options specialist as needed. An omitted specialist configuration stays disabled; routing phrases cannot enable it. The planner sees configured roles only, and the server rejects assignments without a model. All specialists share the existing four-task ceiling.
2. In **Settings → Agents**, separately set each role's instructions, optional trigger phrases and approved company-wide knowledge. Instructions and phrases guide planning without guaranteeing an assignment. Each new supervisor run snapshots those profiles and knowledge alongside its model policy; later edits do not change an existing run. Specialists with at least two model steps can also search approved company knowledge without explicit profile assignment. Searches retain bounded reference excerpts with their findings, never substitute company examples for project evidence, and do not load the whole library into every prompt.
3. Select Team for discussion or Report for a document, then ask for a source-based review. Specialists reuse the saved source facts and excerpts with their provenance and review status, not another extraction. Sound insulation proposes acoustic inputs and can use the bounded arithmetic tools below, construction law flags requirements and applicability uncertainty, and cost options compares evidenced alternatives without invented prices. All results remain subject to human review, not legal advice approval or compliance certification.
4. In Report mode, select **sound-insulation-review v1** for a general review in German or English: scope, sources/revisions, requirements/assumptions, room/component references, findings/conflicts, measures/alternatives, open issues/next steps and review status. Select **interior-noise-concept v1** or **exterior-noise-concept v1** for an Innenlärmkonzept or Außenlärmkonzept respectively. The explicit selection wins over keywords in the request; a Sound insulation specialist alone does not trigger a report in Team mode. The concept formats follow the completed reference reports' distinct section order, with a project cover, numbered PDF contents, component tables, plan references and a calculation-evidence inventory. Missing inputs stay explicit; existing reports do not authorize new calculations or compliance claims. The server saves fixed-section Markdown and the structured template on the artifact revision. Preview and PDF use the same saved prose; optional independent review examines that rendered document. Earlier documents and runs without an explicit workflow retain their previous behavior.

For example: “Erstelle ein Außenlärmkonzept aus den Projektquellen. Trenne belegte Angaben, Annahmen und offene Punkte; übernimm alle vorhandenen Pläne und die vollständige Berechnungsanlage als ungeprüfte Quellenbelege.” Concept authoring reads saved PDF pages beyond short search snippets and writes checkpointed sections rather than forcing the whole report into one response. Existing values are retained as source claims, not treated as absent merely because they are unvalidated. This uses more bounded model calls and may cost more overall; it never raises configured limits automatically. Incomplete or token-truncated responses fail visibly rather than appearing as a completed report.

The saved attachment register identifies exact source versions and PDF page ranges. PDF export includes selected original marked plan sheets, component details and calculation pages after their respective report sections, preserving landscape drawings and original appendix numbering. These are imported, unverified source pages—not new calculations or approval of the draft. Inspect the register for source coverage and obtain specialist review before relying on results. The Markdown preview shows the register; download the PDF to see the actual pages. A missing or invalid attachment stops the export instead of silently omitting it. Template PDFs cannot yet be uploaded or assigned in Settings → Agents; that planned workflow is described in the [template settings direction](/docs/architecture/agent-runtime#planned-template-uploads-in-agent-settings).

Download the server-generated PDF for Richtfest branding on the cover, contents and authored report pages. Original source attachments keep their own artwork and an explicit unverified-source label, not a new Richtfest wordmark. Revision and draft/review status remain visible; branding does not approve the document. Existing saved reports receive the current export layout when downloaded again—no new agent run is needed. The Markdown preview and browser-print action do not include this PDF letterhead.

Room/component links point to an exact source `versionId` and the existing importer's `entity.key` (`entityKey`) and case-preserved `globalId`. Missing identifiers or page references remain null. IFC `#expressID` references are revision-local, not identities across versions. These links are proposals, not newly created BIM records or approved calculation inputs; confirm them against the original and the saved fact review state. See [runtime contracts](/docs/architecture/agent-runtime#review-and-control) for the document and reference limits.

Apply the standard application migrations before configuring profiles: `0028_domain_agent_profiles` permits the new role keys without changing existing settings. The prepared contracts and checked mock-provider execution do not establish real-provider quality or validated engineering behavior.

### Use acoustic arithmetic

Enable Sound insulation specialist in the selected model preset and give it at least two model steps so it can call a tool and read the result. In an ordinary project conversation, ask it to use `sum_sound_levels`, `equivalent_sound_level` or `composite_sound_reduction` where appropriate. For example: “Nutze das Werkzeug zur energetischen Addition der belegten, unkorrelierten Schallpegel am selben Empfangspunkt. Zeige Quellen, Annahmen, Ergebnis und Grenzen getrennt.” The planner must assign that specialist; instructions do not guarantee a tool call.

The tools calculate logarithmic level addition, duration-weighted Leq and area-weighted sound reduction in one frequency band. They require source quotations or explicit assumptions and save an unreviewed receipt with inputs, engine version, formula and intermediates. Reports can use these receipts separately from historical source results. Missing values must stay missing rather than be invented to finish a calculation.

For room-based exterior-noise screening, `exterior_noise_room_requirement` computes a DIN 4109-1/-2:2018-01 target from an already assessed La, room use and complete exterior/floor areas. `exterior_noise_facade` adds installed component Rw and small-element Dn,e,w ratings, orientation corrections and the numerical margin. Example: “Prüfe den Raum mit den belegten La-, Geometrie- und Bauteilwerten über die Außenlärm-Werkzeuge. Fehlende Nachweise, unklare Flanken oder ungeprüfte Einbaubedingungen nicht als erfüllt annehmen.” Unsupported cases produce a saved blocking reason without a number. A positive numerical comparison is not an approved Schallschutznachweis.

This is not a full Außenlärm or DIN 4109/ISO 12354 verification. It does not calculate propagation, flanking, regulatory design levels or compliance, and band sound reduction cannot substitute for Rw, R'w or STC. The separate validated-calculation workflow still reports that a validated engineering tool is unavailable. No database migration is needed for these arithmetic tools. See [runtime contracts](/docs/architecture/agent-runtime#deterministic-acoustic-tools) for receipt persistence and scope checks.

## Archive and restore threads

Archive a thread from its rail row to remove it from the active list for the project. This is a shared, reversible change: messages, sources and agent history remain available, and archiving does not stop running agents. Expand Archived to open or restore a thread. Archiving the selected thread switches to the next active thread, or the start view when none remain. Archive and restore require knowledge write access and record an audit event.

The Agents panel groups active and done runs and lists the supervisor alongside its delegated specialists. Open a run to inspect its conversation. A queued run is labeled as queued, keeps the crane visible in a waiting pose, and says it is waiting for a worker; the crane animation starts once execution begins. While it is running, the conversation shows a compact current-task summary and the latest recorded activity, updating them in place. Supervisor summaries name each active specialist and its assignment, with running work before clearly labeled queued work; once specialists finish, the summary switches to reviewing their findings. These are recorded assignments and activity, not private model reasoning. Expand **Activity history** to inspect the timestamped milestones and retry explanations; the history is collapsed by default and remains available after a run stops. Specialist conversations use the same feed and link back to their source versions and related specialists. Failed and cancelled runs show a recorded reason in run details and in each affected specialist row, including when the supervisor failed and stopped its child runs. Reasons name the phase and a safe failure category without exposing provider exception text. Older runs with only a generic error are identified as having no specific cause recorded. Run details also distinguish worker queue wait, the current supervisor phase, provider-call duration and the last recorded progress. Provider-call events store the phase and an opaque call ID, not prompts, source text, credentials or raw provider errors. Run rows show elapsed time (seconds for the first five minutes, then whole minutes), reported input and output tokens, and an approximate cost when the model's rate is known. Token totals come from provider usage reports; cost is an estimate and is left unavailable when pricing is unknown.

### Understanding live progress

During specialist work, the current-task area identifies the source names and revisions in the current batch and its position in the assignment (for example, batch 2/3). After a batch returns validated structured output, **Findings so far · Not reviewed** shows an excerpt of the saved findings while the next batch runs. This is provisional project content, not an approved result or a private reasoning trace. Expand **Activity history** for the longer saved excerpts, earlier batches and retry details.

New specialist assignments use larger, page-aware source batches when the selected model has a known context capacity. Output-token and summary limits stay unchanged. Independent specialists start as soon as the preset's parallel capacity is available, without waiting for the slowest member of a fixed group. Batches within one specialist remain sequential so later findings build on earlier ones. **Retry run** preserves an older assignment's small batches and completed findings; use **Run again** or a new request to apply the larger layout. Unknown models retain conservative batching.

During acoustic concept drafting, the batch counter reports completed pieces for the named report section, not progress through the whole run. Up to three pieces across different sections can run at once, depending on the run's saved preset; short sections no longer wait for earlier sections to finish. Completed pieces are retained even when they finish out of order, and the document keeps its required section order. Retry run fills the gaps without rewriting saved pieces. New outlines avoid drafting overlapping source-page selections twice. Retrying an older draft keeps its original batch layout to preserve completed work. Parallel calls can shorten the wait, but do not by themselves reduce token costs, and provider rate limits still apply.

Once sections are assembled, progress shows whole-report consolidation, then a separate check that the edit preserves evidence. Only a passing preservation check proceeds to optional independent source review and artifact publication. The original calculation appendix, metadata and original PDF attachments are unchanged. The edited candidate and check result are saved durably: **Retry run** resumes a saved candidate after a checker timeout, while an explicit retry after rejection edits again using the saved feedback. Incomplete, oversized or failing checks publish no artifact; a published draft still requires human review.

New drafts on models with a verified context capacity use larger, page-aware batches—often a whole report section per request—instead of many tiny chunks. The runtime reserves room for instructions and output without changing your model or output-token setting. If a larger batch cannot produce complete output, only that batch falls back to smaller, individually saved pieces; incomplete text is never published as a finished report. Unknown models retain conservative batching. Use **Run again** or start a new request to apply the new layout to an older stopped draft; **Retry run** deliberately preserves its saved layout and work. Neither action approves the resulting document.

Preparation, source-free evidence-gap checks, supervisor synthesis, independent review and requested revisions have distinct activity descriptions. Progress updates at actual work boundaries, not on a timer or every model token; a long provider call may keep the same description until that batch returns. There are no additional model calls for progress. Reopening a run restores its saved events. Older runs without these events fall back to their recorded assignments and milestones.

## Explore agent costs

Open the project's **Analytics** tab to browse coordinator and supervisor runs, newest first. Expand a run to see each agent's own estimated USD cost, models, usage-record count, input, output, reasoning and cached-input tokens. The run total includes every descendant, including older subagents outside the conversation's recent-run list. Agent rows and **Open run** link to the existing run details. **Older runs** and **Newer runs** page through groups of 20 coordinators without splitting their agent breakdowns.

**Project totals** cover the entire project, not just the visible page: run count, recorded tokens, recorded estimated USD cost and average tokens per run. A coordinator plus all its descendants counts as one run. The average includes only inactive run trees with complete input and output usage for every agent and recorded attempt; **Measured runs** shows how many qualify. Active and incomplete runs still contribute known usage to the totals. Missing values stay unavailable rather than becoming zero.

**Usage by model** groups saved usage by provider and model, showing usage records, input, output, total, reasoning, cached-input tokens and recorded estimated cost. Total tokens means input plus output; reasoning and cache are subsets, not extra tokens. A missing model ID appears as **Unknown model**. Calls without saved usage may not be attributable to a model and are flagged in the project totals instead of assigned invented values.

**Partial · recorded only** means the displayed amount is only the known priced usage, not a full total. Expand the row to see counts of calls missing usage, unpriced usage records and agents with no usage records. **Unavailable** means no priced usage is known; it does not mean zero cost. Historical usage stays with the agent it was originally recorded against. Reasoning tokens are part of output tokens and cached input is part of input, so do not add those columns together.

Choose **Refresh costs** to fetch the latest recorded values; active runs show costs so far. These are model-rate estimates, not provider invoices, and exclude conversation title generation, source processing and hosting. Analytics uses existing project and knowledge read access; it does not introduce a separate permission.
